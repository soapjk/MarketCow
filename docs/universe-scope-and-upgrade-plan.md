# MarketCow：市场范围热切换与软件升级设计及待办

日期：2026-09-08。本文取代原冷安装方案；描述目标设计与开发待办，不表示已经部署。

## 1. 两类变更的边界

| 场景 | 处理方式 | 是否必须保持服务在线 |
| --- | --- | --- |
| Tradude 因策略/行情变化调整 1000 或 250 名单 | 同版本市场范围热切换 | 是，准备期间旧范围继续供数 |
| 服务架构、接口或行情数据格式跨版本变化 | 协调停机、直接替换程序，必要时重建行情数据 | 否，不要求软件无缝升级 |
| 中断太久、增量已超保留窗口 | 明确 resync，重新 full-sync；必要时重建受影响源状态 | 不强求旧游标连续；不把单市场故障扩大成全池重建 |

**业务换市场需要热切换；软件换版本不需要热升级。**
热切换不代表所有新增市场立即可交易，也不代表客户端完全无需同步。
服务要持续发布，范围变化要有明确边界，不能混用新旧名单和基线。

## 2. 目标能力与职责

```text
真实全目录 → Tradude 选择 1000 → Discovery 在线更新范围
  → 实际报价 → Tradude 选择 250 → Live 在线更新范围
  → 下游安装新基线 → 原 Paper 账户继续运行

后续策略变化：重复在线更新，不重启正式服务
软件不兼容升级：另走停机替换、必要时重建行情数据
```

- Tradude 拥有两层名单、排名规则、持仓/待执行保护和交易资格。
- MarketCow 负责源事实、身份/依赖、采集、资源准入和发布；不自动补满或替换策略名单。
- 正常池大小为 1000/250；支持明确小名单，依赖市场与实际采集 token 单独计数。
- Rust 直接提供 Discovery `192.168.124.3:8795`、Live `192.168.124.3:8793`。
- loopback `127.0.0.1:18898` 继续作为独立鉴权控制面，不转发行情。
- 缺盘口、恢复和过期只影响相应市场/策略依赖闭包，不要求整个池全部健康。
- 5 秒新鲜度仍由 Tradude 策略判断，不作为全池发布门槛。
- 实时行情内存直接发布，持久化独立异步且有界；不重新引入 Python 行情中转或磁盘发布锁。

## 3. 同版本市场范围热切换

### 3.1 最小执行流程

1. **接收明确名单。** 绑定 pool、catalog revision、selection hash、预期 active revision、策略版本与保护身份。
   Live 还绑定父 Discovery selection 和明确池外保护例外。拒绝重复、保护遗漏与资源超限，不静默补齐。
2. **计算差集及闭包。** 区分 retained/added/removed。保留市场复用仍有效的订阅、盘口与质量状态，
   不因名单变化清空整池。关系所需成员完整保留，缺项显式报告。
3. **在线准备新增项。** 旧池继续发布；新增订阅/快照在明确时间、token、内存和字节预算内进行。
   最多一个待切候选。超出切换瞬时容量时拒绝或延后，不先淘汰旧池腾位置。
   新增项未就绪可以作为 missing/recovering 随新范围发布，不等全部健康。
4. **原子提交范围。** 再次比较预期 active revision，提交完整成员、依赖、基线及确认基线绑定。
   过期并发请求不能覆盖新名单，准备成功或 desired 写入不等于已经生效。
5. **通知下游。** 发布明确范围变化边界。首版允许客户端重新 full-sync/ready，
   不要求同时实现范围差异快照。过渡期暂停受影响策略评估，不停止整个 Paper 或删除账户。
   旧范围在明确期限内可读，旧连接不能混入新范围事件。
6. **退役旧订阅。** 到期释放没有新池、依赖或保护引用的订阅/状态。慢客户端超期须重新同步，
   不得无限拖住旧状态。准备失败只释放候选，旧池继续供数。

### 3.2 身份与游标不能混为一谈

- release/binary hash 是软件版本；selection/revision 是市场范围；instance/projection 是流实例。
- 范围变更不必伪装成软件升级。复用同实例时保持原有游标单调语义；创建新实例时安装新基线，
  不跨实例比较游标数值。
- 基线的成员、依赖、盘口版本与确认状态必须属于同一范围边界。确认不能先于对应盘口被应用，
  不能借切换刷新陈旧盘口时间或恢复 gap。
- Discovery 保留自身 full-sync/delta/projection 语义，不伪造 Live ready。

### 3.3 最少管理契约

保留 prepare / activate / status 的必要语义，复用已有 canonical、鉴权、幂等和 revision 比较，
不另造通用部署平台。具体 wire 与 Tradude 对齐后实现，不把本文逻辑名称冒充已部署路由。

- prepare：明确名单、父绑定、预期当前范围和资源配置；返回候选身份、完整成员及质量事实。
- activate：候选身份 + 预期 active revision；实际发布后返回新范围/流身份、基线与同步要求。
- status：区分 preparing、prepared、active、failed，不把 desired 当 actual。
- 控制面恢复后核对实际 Rust active revision，保留小型操作结果；不要求无限 generation 历史。
- 只保留当前范围、一个待切候选及有限期旧范围。失败前旧池保留是必要能力，
  自动回退整个软件版本、跨版本双运行不是必要能力。

**systemd 停旧 unit、改链接、再启动只属于软件部署，不算市场范围热切换。**
现有独立候选预热只能证明候选能运行，不能代替 Rust 在线范围发布。

## 4. 软件升级与行情重建

软件不兼容时允许：协调保存 Paper → 停目标服务 → 替换程序/配置 → 按需清理不兼容行情状态
→ 原端口启动 → 新 full-sync/ready → 原账户续跑。不做旧行情格式迁移、跨版本游标继承、
软件零停机或自动回退框架。失败明确报告阶段，修当前版本再启动。

可重建：目标 MarketCow 盘口/恢复状态、最近事件、行情游标、确认基线、SQLite/JSONL 和派生索引。
只清理明确受管路径，先停止写者，不跟随符号链接越界，不删除唯一可信源原件。

不可随行情删除：Tradude Paper 数据库、余额、持仓、待执行、成交审计及防重复成交/流动性消耗记录。
新行情实例不能把同一已消耗盘口当作新流动性。短暂单实体故障继续局部恢复，不滥用全量重建。

## 5. 逐项开发待办及做法

### M1：目录指标与源刷新 — MarketCow

- 复用 mapper、目录准备与抓取程序，贯通真实 volume/liquidity、明确单位、decimal 数值、来源和时间。
  修复正式部署仍全 null 的接线问题，真缺失继续 null。
- 有界刷新完整源目录并规范化，报告 coverage 和排除项；旧目录不冒充当前活跃事实。
- 首批提供一次性刷新及固定 revision 分页，目录增量变更流不阻塞交付。
- 输出：Tradude 实际可用于策略筛选的目录。

### M2：Rust 在线范围更新入口 — MarketCow，核心缺口

- 在现有运行时接入受信任控制命令；外部走独立鉴权，不能提交机器路径或 shell 命令。
- 复用 source plan/依赖构建和身份校验，计算 added/retained/removed，在线调整采集和发布范围。
- 保留项不中断采集，新增项有界初始化，移除项按引用释放；不重启正式 collector。
- 复用 cold candidate 的解析/配置代码，不将其 systemd 启停流程当作热切实现。
- 输出：同版本正式服务运行期间接受新范围的能力。

### M3：准备/激活接口及当前范围绑定 — MarketCow

- 接通 admission、实际在线准备、activate 和 status；直接返回可由下游使用的范围和基线。
- 修复固定 legacy incumbent、固定最初发布配置的问题：范围操作读取实际 active selection/revision，
  使用预期 revision 防覆盖，不继续固定最初的旧名单，也不能读取未生效 desired 冒充当前范围。
- 软件 unit 版本绑定与市场范围状态分离，不为连续换池维护一串部署配置。
- 输出：连续两次策略换池可执行，结果代表实际生效，不是登记候选。

### M4：原子范围边界与有界退役 — MarketCow

- 同一边界绑定完整成员、依赖、盘口与确认基线；发布指针为轻量步骤，不等全池就绪或落盘。
- 明确旧范围保留期限、客户端同步边界；准备失败保留旧池，超期客户端重新同步。
- 补齐候选释放、订阅引用计数和旧范围清理，避免失败候选和移除市场长期占资源。
- 拆分 requested、metadata closure、实际 acquisition 和切换瞬时预算。
  已知旧 1000 的 5746 个闭包 token 不能被误当作 5746 个实际订阅 token。
- 输出：范围切换不混状态，连续更新不无限增长资源。

### T1：真实 1000 名单与请求 — Tradude

- 读取 M1 目录，按明确策略生成 selection 和保护名单，不以 ID 排序或 incumbent 冒充新策略。
- 接入 prepare/activate/status，名单变化不再要求人工重启服务。
- 输出：第一个新 1000，以及后续策略更新请求。

### M5：Discovery 1000 热更新 — MarketCow

- 将 M2—M4 接到 Rust Discovery；使用现有报价/关系协议。
- 区分实际采集、关系元数据及未报价依赖，不以 Gamma 历史价格冒充盘口。
- 输出：8795 持续服务，新 1000 生效并提供真实报价。

### T2：250 选择及账户/范围同步 — Tradude

- 基于新 1000 实际报价评估质量、深度、机会，产生 250；绑定父 selection 和保护例外。
- 迁移仍拒绝 null 结束日期的旧模型，保持已约定未知日期/30 天规则。
- 范围变化时暂停受影响评估，安装新 full-sync/ready/confirmation 基线，不清账户、不混旧行情。
- 软件升级或长中断另走完整源重同步，仍保留精确消耗和防重复执行约束。
- 输出：支持业务热换范围与软件冷恢复的消费者。

### M6：Live 250 热更新 — MarketCow

- 将 M2—M4 接到 Rust Live，核对已生效父 Discovery selection、持仓保护例外及完整依赖。
- 保留实体顺序和局部恢复，新市场缺数据仅影响相应策略；8793 正式服务不因换名单重启。
- 输出：新 250 在线生效与真实运行回执。

### M7：本次软件部署与垃圾清理 — MarketCow

- 为安装新增能力允许按第 4 节停机升级；升级后的策略换池必须使用在线路径。
- 清理无进程/正式配置引用的失败候选、重复产物和不兼容行情状态，保留小型清理记录。
- 复用已有有界历史与日志轮转，不扩写跨软件版本自动退役平台。

### T3：原 Paper 使用完整流程 — Tradude

- 原账户接入新 250，继续运行并响应后续范围更新，不重建账户。
- 无机会、现金不足或部分市场不可用允许零新增成交，不造数据或自动补资金。

## 6. 执行依赖与完成定义

| 顺序 | 输出 | 可提前开发的部分 |
| --- | --- | --- |
| 1 | M1 目录事实；M2—M4 在线范围基础 | 两条实现线独立，不等排名结果才能开发运行时 |
| 2 | T1 新 1000；M5 Discovery 接入 | Tradude 请求适配可先依据契约实现 |
| 3 | T2 报价选 250；M6 Live 接入 | null 日期、范围同步和账户分离可提前完成 |
| 4 | M7 本次软件部署 | 允许停机，但不把这次启停当作热切成功 |
| 5 | T3 原账户使用；同版本再换范围 | 不重启正式服务，不以首次安装代替动态能力 |

完成目标：真实目录 → 策略新 1000 → 实际报价 → 策略新 250 → 原 Paper 使用，
且后续同版本范围更新无需重启正式服务。
范围原子性、并发旧请求拒绝、准备失败旧池供数、局部缺失、持仓保护与资源有界属于功能本身。
修改实时链路仍遵循项目异步持久化、实体隔离、慢消费者和队列上限的强制要求，
不额外扩大成无关的长期性能研究或“全池全部健康”门槛。

不要求：软件跨版本无缝升级、旧行情格式兼容、自动软件回退、全市场秒级扫描。
当前已有 cold preheat/systemd 工具可用于软件部署。Rust 在线范围发布、WS/REST 管理命令、
有界退役和重启状态日志已经写入候选；外部鉴权路由也已接线，但尚未部署或完成真实链路交付。
构建与分层证据见 [实现进度](universe-generation-adapter.md)，不能用它们替代上述完整目标。
